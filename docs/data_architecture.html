📦 bertrend.dill
1 file
<watch>/bertrend.dill
Origin

Produced by bertrend.save_model(path) at the end of each training/update pass. Serialized via the dill library.

Role

Single, complete container of the watch state. Opened via BERTrend.restore_model(Path).

Contains

All global topics, all merge/emergence events, raw texts and embeddings grouped by period, the config, and the last trained BERTopic.

Does not contain

The BERTopic instances of previous periods. The size of topic -1 per period. The noise/weak/strong classification. The LLM interpretations.

Config and metadata
config
dict (6 keys)
Watch hyperparameters (file bertrend_default_config.toml).
Default values (bertrend_default_config.toml)
{ "granularity": 2, # number of days per period "min_similarity": 0.7, # cosine threshold for merging "decay_factor": 0.01, # Popularity decay amplitude "decay_power": 2, # decay power "signal_classif_lower_bound": 10, # lower percentile ("Q1") "signal_classif_upper_bound": 75, # upper percentile ("Q3") }

🧠 interpretation/
Derived analyses
<watch>/interpretation/YYYY-MM-DD/
Origin

Post-training pipeline. Classification via _classify_signals(), which applies Q1/Q3 thresholds. .jsonl files via the analyze_signal() LLM call.

Role

Make signals actionable — classify each topic and generate analysis text.

Contains

At a given date: classification of every known topic + optional LLM interpretation.

Does not contain

Raw data (embeddings, texts, histories). These files are analytical projections.

Signal classification
strong_signals.parquet
Parquet → DataFrame
Topics classified as strong (Popularity ≥ Q3, where Q3 = 75th percentile by default, not the classical quartile).
Columns (12)
ColumnDescription
TopicID (references merged_df.Topic)
RepresentationKeywords joined by _
Latest_PopularityPopularity at the date
Docs_CountCumulative articles
Paragraphs_CountCumulative segments
Source_DiversityNumber of distinct sources
Latest_TimestampLast update
DocumentsDocument history (list[str])
SourcesContributing sources (list[str])
URLsArticle URLs (list[str])
LLM TitleHuman-readable title generated by LLM (short summary)
LLM Description~50-word description generated by LLM
⚠ LLM interpretation tiers

The LLM Title/LLM Description columns are generated for almost every topic (broad coverage, 1 call per topic). Deep interpretation (timeline + foresight) lives in the .jsonl files and only covers ~5-10 topics per snapshot.

Load
df = pd.read_parquet("strong_signals.parquet")
weak_signals.parquet
Parquet → DataFrame
Weak topics (Q1 ≤ Popularity < Q3 — Q1 = 10th percentile by default).
Notes

Same schema (12 columns, including LLM Title and LLM Description). The most interesting file for monitoring: topics on the rise but not yet established.

noise.parquet
Parquet → DataFrame
Noise topics (Popularity < Q1).
Notes

Same schema (12 columns) — usually the largest file. The Q1/Q3 thresholds used here are the keys signal_classif_lower_bound (10) and signal_classif_upper_bound (75) in bertrend.config — these are percentiles, not the statistical quartiles (25/75).

LLM interpretations

JSON Lines

Cross-references and redundancies
Redundant last_topic_model (.dill) ≈ the snapshot of the last period. Same content, different format.
Redundant merged_df["Documents"] and doc_groups overlap — same texts indexed differently.
Derived *.parquet produced by _classify_signals() from topic_sizes. Recomputable.
Derived *.jsonl produced by the analyze_signal() LLM call. Recomputable with an API key.
Lost without snapshot Topic -1 size and per-doc→local-topic mapping at T. The .dill does not track them.
Watch out topic_sizes can be empty on disk. Re-run calculate_signal_popularity().

bertrend.train_topic_models(grouped_data, embedding_model, embeddings, ...)
Trains one BERTopic per period and fills the BERTrend object (doc_groups, emb_groups, last_topic_model). Loops and calls merge_models_with at each new period.
Input grouped_data, embeddings
Output fills .dill writes snapshots (if save_topic_models=True)
Note

Not used during exploration. Documented to explain the upstream pipeline.

bertrend.merge_models_with(new_model, timestamp, min_similarity=None)
Merges a new BERTopic (period T) with the last trained BERTopic (T-1). Called in a loop by train_topic_models. Feeds merged_df, all_merge_histories_df, all_new_topics_df.
Input new BERTopic + Timestamp last_topic_model, doc_groups, emb_groups
Output merged_df (updated) all_merge_histories_df (append) all_new_topics_df (append)
Note

There is no merge_all_models() method. Merging is incremental at each period.

📌 Usage guide — which source for which need
Analyze global topics
Source: merged_df (.dill)
One row = one global topic. Dominant subjects, sizes, recent keywords, semantic centroids. Everything answering "what are the big subjects of my watch over its whole duration".
Retrieve a global topic's documents
Source: merged_df["Documents"] (.dill)
List of [(timestamp, [texts])]. Warning: outliers (Topic = -1 of local BERTopics) are NOT inside — they never join a global topic.
Individual-doc-level embeddings
Source: emb_groups (.dill) — mandatory
The only place that holds each doc's embedding. merged_df.Embedding only stores the topic centroid. Required for doc-level UMAP, doc-to-doc similarity, semantic search.
Docs per period, chronological order
Source: doc_groups (.dill)
Dict {period: [texts]}. Contains ALL docs (including future outliers). Order preserved, aligned by index with emb_groups.
A doc's local topic at period T
Source: doc_info_df.pkl of the T snapshot
The Topic column gives the local ID (-1 for outliers). Positional correspondence with doc_groups[T].
Isolate outliers at a period
Source: doc_info_df.pkl of the snapshot — filter Topic == -1
Impossible from the .dill alone: outliers leave no trace in the event logs.
Popularity history of a topic
Source: topic_sizes[topic_id] (.dill)
Series Timestamps, Popularity, Docs_Count, Paragraphs_Count. EMPTY until calculate_signal_popularity() is called after restore_model.
Weak/strong signal detection
Source: interpretation/YYYY-MM-DD/*.parquet
Classification already computed (Popularity vs Q1/Q3). weak_signals.parquet is the most interesting. Recomputable from topic_sizes via _classify_signals.
Understand a topic's history (merges)
Source: all_merge_histories_df filtered on Topic1 == id
Each row = one merge. Representation2 gives the keywords of the absorbed local topic — lets you follow semantic drift.
LLM interpretation of a topic
Source: *_interpretation.jsonl (interpretation/)
Summary, drivers, short/long-term implications generated by LLM. Often empty on the server side — recomputable via analyze_signal() with an API key.
